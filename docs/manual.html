操作手冊

每一步用哪個腳本、怎麼執行、產出什麼。想先了解原理請看原理教學。下面所有指令都在倉庫根目錄執行，python 指的是裝好套件的 Python（這台電腦上是 conda 環境 speaker-mask）。

倉庫結構

位置內容
pipeline/主流程程式。run_all.py 依序執行全部；config.py 從 settings.yaml 讀取所有路徑。
tools/check_env.py檢查 Python 套件、GPU、設定的路徑與 COLMAP；可自動下載 COLMAP。
tools/build_site.py從本機結果產生 docs/ 網站（合成圖、資料、圖表、結果檔）。
tools/coarse_annotation_ui.py粗框標註工具（在 DJI 幀上拖框並指定編號）。

settings.example.yaml路徑設定範本。複製成 settings.yaml（不上傳）後修改。

docs/本網站（GitHub Pages）。

不在倉庫中：Sony 與 DJI 原始影像、COLMAP 資料庫與模型、特徵快取（約 1.5 GB）、本機的完整輸出（含 1600 px 預覽圖）。這些放在 settings.yaml 指定的位置。

安裝與設定

1. 取得程式

git clone https://github.com/wangpenghao468-collab/wfs-speaker-localization.git
cd wfs-speaker-localization

2. Python 環境

需要 Python 3.10 以上，以及 NumPy、OpenCV（4.4 以上，含 SIFT）、Pillow、PyYAML、PyTorch（CUDA 版，用於 GPU 特徵匹配；沒有 GPU 也能跑，但慢很多）。

conda create -n wfs python=3.10 -y
conda activate wfs
pip install numpy opencv-python pillow pyyaml
pip install torch --index-url https://download.pytorch.org/whl/cu118

3. 設定路徑並檢查

copy settings.example.yaml settings.yaml
python tools/check_env.py

用文字編輯器打開 settings.yaml，把每一行改成資料在你電腦上的位置（可用相對路徑，相對於倉庫根目錄）。check_env.py 會逐項列出 ok 或缺少什麼。COLMAP 只有重建或做光束法平差時才需要，可以用 python tools/check_env.py --download-colmap 自動下載 3.11.1 版。

這台電腦上目前的環境：Python 3.10、OpenCV 5.0、PyTorch 2.5.1 + CUDA 11.8（RTX 4090）、COLMAP 3.11.1。

A. 標註編號（你操作）

SAM2 振膜遮罩 / 粗框

目的
112 顆外觀相同，必須由人指出「哪一顆是幾號」。只要標一部分，其餘由「8 顆一架」規則補齊。
工具
粗框：python tools/coarse_annotation_ui.py（需要 pip install gradio，瀏覽器開 127.0.0.1:7861）。SAM2 遮罩工具目前只在原電腦上（work/speaker_mask_ui），模型見 facebookresearch/sam2。
輸出
masks/manual_mask_annotations.csv、coarse_annotations/speaker_boxes.json
注意
左右兩側幾乎一樣，容易標錯側（frame_00059 曾標成 16–31，實為 80–95，已更正）。

B. COLMAP 重建（已完成，一般不需重跑）

技術
COLMAP 3.11：SIFT 特徵、順序與詞彙樹匹配、增量式重建。
結論
DJI 連續影片的模型正確，當作座標基準。Sony 模型把左右兩側摺疊在一起（938 張只註冊 396 張），只用它的資料庫匹配和局部相對關係。
平差
曾用 pipeline/ba_sony.py 對 Sony 照片做光束法平差，三種設定都比現在差（Sony 照片分成 333 個互不相連的小群，會各自漂移），沒有採用。詳見原理教學第 13 章。

C. 主流程 14 步

一次執行全部：

python pipeline/run_all.py

也可以單獨執行任一步，例如 python pipeline/identify.py。時間是這台電腦、特徵已快取時的大約值。

1. sony_cameras.py < 1 分

做什麼
準備每張 Sony 照片的鏡頭參數：已註冊的用 COLMAP 校正值，其餘按 EXIF 焦距套用同焦距的校正值。
輸出
sony_intrinsics.json

2. detect_diaphragms.py 約 10 分（新照片才計算）

做什麼
找銀白色振膜：HSV 門檻（V > 140、S < 60）、連通區域、圓度 ≥ 0.6、暗環 ≥ 35%，取質心並去畸變。
輸出
detections.json

3. dji_speakers.py < 1 分

做什麼
把你的標註在 DJI 模型中三角化（多幀 DLT；單幀時用點雲深度）。標錯時會出現上百像素的誤差。
輸出
dji_speakers.json

4. dji_bars.py < 1 分

做什麼
8 顆一架、共線等距，用 RANSAC 擬合全部 112 顆的大約位置，並由架內 80 mm 決定尺度。
輸出
dji_bar_model.json

5. localize_sony.py 首次約 1 小時；快取後 10–15 分

做什麼
每張 Sony 照片與 DJI 幀做特徵匹配，取得 2D–3D 對應，以 PnP RANSAC 求相機位姿。
技術
RootSIFT（3000 px）、GPU 雙向最近鄰 + 比值測試、AP3P/SQPnP/EPnP RANSAC、LM 精修。
輸出
sony_in_dji.json、corr/、feats2/（特徵快取）

6. consensus_poses.py 15–25 分

做什麼
鄰居投票：用照片之間的相對旋轉與位置（共視 ≥ 40 點，或資料庫驗證匹配 ≥ 60）檢查每個候選位姿，排除被配到對側的照片。網站回報的錯誤是硬性條件。
輸出
sony_poses_final.json（663 張）

7. identify.py 約 5 分

做什麼
把每顆喇叭投影到每張照片，要求完整在畫面內、面向相機、附近有大小合理的振膜偵測（0.25 間距內，且明顯比第二近的近）。
輸出
speakers_final.json

8. triangulate_centers.py 約 1 分

做什麼
DLT 初值 + Gauss–Newton 最小化重投影誤差。自適應 Huber 權重（2.45σ）、整張偏移照片排除（> 25 px 且 > 3 倍典型值）、視角 ≤ 75°、清晰度 ≥ 50、bootstrap 200 次。
輸出
centers.json、speaker_centers_mm.csv

9. floor_height.py 3–5 分

做什麼
Sony 照片兩兩三角化地磚點，穩健擬合地板平面，算出每顆的離地高度。run_all.py 會再跑一次第 8、9 步，讓座標建立在新地板上。
輸出
floor.json、speaker_heights.csv

10. compare_design.py ／ 11. export_panoramix.py < 1 分

做什麼
讀設計檔的 /bus/10/speakers/aed，以水平旋轉 + 平移（不縮放）對齊；架子直線的法線為朝向；寫出只改兩行的設定檔副本（保留原換行格式）。
輸出
1012_measured.txt、panoramix_bus10_measured.txt/.csv、design_vs_measured.csv

12. 圖 < 1 分

腳本
plot_design_vs_measured.py、plot_heights.py、plot_overlay_topview.py

13. build_finder.py 1–5 分

做什麼
本機版照片查找頁的資料：1600 px 預覽圖、data.js、speaker_photos.csv。網站版由 tools/build_site.py 再從這裡產生。

14. verify_bars.py 約 2 分

做什麼
每根架子抽幾張照片標上編號拼成一張圖，用來人工檢查；--unregistered 只用 COLMAP 未註冊的照片。

常見操作

回報編號錯誤

  1. 在照片查找點照片放大，按「編號不對」輸入正確號碼，或按「不是喇叭」「整張照片編號錯誤」。回報存在你的瀏覽器裡。
  2. 按上方「錯誤回報 (N) ⤓」下載 speaker_corrections.json，放進 output_dir（或留在「下載」資料夾，程式會找最新的一份）。
  3. 執行 python pipeline/run_all.py，再更新網站。

新增照片

把新的 JPG 放進 Sony 照片資料夾，檔名加到 sony_selected_list，再執行 run_all.py。要讓新照片參與鄰居投票，需要先用 COLMAP 把它們加入 database.db 做匹配；否則只能靠自己的定位。補拍時每移動一步多拍一張重疊的照片，效果最好。

只更新 Panoramix 檔（例如改了設計原點）

python pipeline/compare_design.py
python pipeline/export_panoramix.py

重新量測（喇叭移動過）

在 settings.yaml 把 measurement_dir 改成新日期（例如 measurements/2026-12-01），用新的照片資料夾和新的 work_dir、output_dir，執行 run_all.py。舊的量測結果會留著，可以比較。

更新網站

在檔案總管雙擊倉庫根目錄的 上傳更新.bat，或執行：

python tools/build_site.py
git add -A
git commit -m "update results"
git push

推送後約 1–2 分鐘，GitHub Pages 會更新。

重要參數

參數值位置意義
架內間距8.0 cmdji_bars.py IN_BAR_CM整個系統的比例尺
鄰居門檻40 共視點 / 60 匹配consensus_poses.py多少共同特徵才算鄰居
位姿一致容差約 5 cm、4°consensus_poses.py兩個假設算「同意」的範圍
振膜配對門檻0.25 間距；半徑 0.11–0.30 間距identify.py投影附近多遠、多大的偵測算數
Huber 門檻2.45σtriangulate_centers.py超過就降權
整張照片排除> 25 px 且 > 3 倍典型值triangulate_centers.py位姿錯誤的判斷
視角 / 清晰度≤ 75°、≥ 50triangulate_centers.py可用來算中心的照片
地板候選帶±40 mmfloor_height.py取地板點的範圍

後續：移動 / 碰撞檢查（設計中，尚未實作）

  • 流程：拍 30–40 張（每根架子 2–3 個角度）→ 只用牆、地板等固定背景定位相機 → 以整根架子擬合平移和旋轉 → 判斷。
  • 門檻：< 2 mm 且 < 0.3° 不用處理；2–5 mm 只更新該架；> 5 mm、> 1° 或單顆與架子不一致時重拍該區。
  • 建議：在牆面和每根架子兩端貼 AprilTag，單張照片就能量出架子位置，也不會左右認錯。
  • 基準：每次都和 2026-10-13 這次的結果比，不和上一次比。
